# 工作日报

从 Git 与对话存档整理用户本人昨天或指定日期的工作，写成可直接上交领导的中文日报。

## 触发后必做

1. 确定日期：说昨天则用会话当天的前一天；指定 10.8、9.28 则用该日。
2. 收集材料：
   - git log / git status 该日相关提交与未提交改动
   - agent-transcripts 中该日的 user_query，必要时看助手收尾结论
3. 只写与项目业务相关、且对话里确认落地的实事。
4. 用下面格式输出。不要只口头总结不写正文。

## 写什么 / 不写什么

写：功能改动、线上同步、数据补齐、问题排查结论、业务页面优化等。

不写：
- 清电脑、腾磁盘、清缓存、装软件等与项目无关的杂务
- 个人闲聊、写群文案、问专利等非本职项目汇报内容，除非用户点名要写
- 空泛计划、未动手的讨论过程

## 输出格式

```text
日报 10月8日

短段落1。
短段落2。
```

- 标题固定：日报 10月8日，不要任何括号。
- 正文短段落，一段一件事；不要编号列表。
- 站在用户角度向上级汇报；我可省略，用查了 / 改了 / 已同步陈述。
- 大白话，正常中文，少 AI 腔。
- 少用技术黑话，领导能听懂为准。
- 禁止按时段叙述：不要写上午、下午、早上、傍晚、中午、晚上等。按事情本身写，不要按钟点分段。

## 口吻

这是用户本人给领导看的汇报，不是助手对用户说话。

禁止：按你要求、按你说的、你确认后、跟你对过、请你验收  
改用：按计划、经核对、已同步上线、已完成

## 表达要写清楚

别写含糊或内部黑话，换成正常人会说的句子。

| 别写 | 改成类似 |
|------|----------|
| 自动落到报修那天 | 点查看设备会指定到报修那天 |
| 灌库 / 导库 | 把本地算好的数据同步到云服务器 |
| 半截日 | 当天数据存早了、只存了半天，后面没更新 |
| 全量重算 / 回填 | 把历史数据重新算一遍 / 把以前缺的天数补齐 |
| 物化 / 缓存 / cron | 后台提前算好存着 / 定时自动补数 |
| OpenAPI / 3s / 1m | 设备平台接口 / 细数据 |
| 前端只读缓存 | 打开页面直接看已有结果，不再现场慢慢算 |
| 部署 dist / 上云 | 更新到线上网站或服务器 |
| 404 / ready / keepAlive | 省略或换成还没开通 / 已经算好 |

## 标点禁用强制，全文零容忍

正文与标题中一律不得出现下列符号，一个都不行：

- 方括号半角全角
- 圆括号半角全角
- 直角引号
- 英文引号夹按钮名

按钮、菜单名直接写进句子里，例如：维保工单里点查看设备会指定到报修那天。

需要补充说明时用逗号或另起一句，不要夹注。  
不要加粗整句；输出里不要表格；不要一二三长标题。

## 示例

差：

```text
日报 10月8日

下午梳理了本地做到一半的功能。维保工单点查看设备会自动落到报修那天。清理电脑缓存腾出大约 16G。
```

好：

```text
日报 10月8日

维保工单里点查看设备会指定到报修那天。

设备详情提前算好的数据暂不上线，避免线上无数据；其它改动已更新到线上。
```

## 与项目更新记录的区别

- 本 skill：给人看的工作日报。
- docs/项目更新记录.md：工程变更文档；仅当用户说更新完 / 记录更新时按项目规则写入，不要把日报误写成更新记录。
